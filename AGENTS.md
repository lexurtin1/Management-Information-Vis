# Agent rules — Pulse platform rebuild

## Context

Two folders are open in this workspace:

- `pulse-reference/` — the original prototype. **Read-only.** Never edit, stage, or
  commit anything here. Use it only to read implementations you are porting.
- `pulse-platform/` — the new repo. **The only writable target.** Everything you
  create goes here.

The job is to rebuild the prototype as a generic enterprise product with
synthetic data. The original contains real proprietary commercial data and real
client names. None of it crosses into `pulse-platform`.

---

## Hard constraints

These are not stylistic preferences. A change that violates any of them is wrong
and must be reverted.

### 1. Never copy these from the reference

| Path | Why |
| --- | --- |
| `pulse/tools/network-overview/**` | Contains `window.CALASTONE_FLOWS` and `window.CALASTONE_SETTLEMENTS` — real order-routing volumes |
| `pulse/tools/network-overview/data/countries.js` | Real market assessments |
| `pulse/tools/market-research/data/countries.js` | Duplicate of the above |
| `pulse/tools/account-tracker/app.js` | Real accounts, named contacts, meeting notes |
| `pulse/tools/calastone-intelligence/**` | Real client names throughout prompts and fixtures |
| `Order Routing Flow - standalone.html` | 1.2 MB, unaudited |
| `pulse/assets/**` | Real headshot and client wordmark |
| `.env`, `AI_BRIEF.md`, `.claude/**` | Credentials pattern and internal briefing |

If you need logic from one of these, read it and **rewrite** it. Do not copy the
file and edit in place.

### 2. Banned strings

No file in `pulse-platform` may contain any of these, in any case, in code,
comments, commit messages, or generated data:

**Company / product:** Calastone, CALASTONE, calastone, Pulse (as a Calastone
product name — the new product name comes from config)

**Real firms:** BlackRock, Goldman, Goldman Sachs, HSBC, Vanguard, abrdn,
Aberdeen, Schroders, Fidelity, Invesco, Hargreaves Lansdown, Hargreaves
Lansdowne, FNZ, Pershing, Transact, Euroclear, EMX

**Named tools:** Salesforce, Jira, Confluence, Power BI, PowerBI, Granola, Neon,
Atlas (as a product or assistant name)

**Real people:** any personal name carried over from the reference, including
contact names in account fixtures.

### 3. Never carry a real number across

Every figure — order volumes, AUM, automation rates, opportunity scores, pipeline
values, headcount — is synthetic and generated by the seeded mock layer. Do not
read a number out of the reference and reuse it, and do not derive one from it.
If you need a plausible figure, generate one.

### 4. Generic equivalents, not deletions

Named systems become **source types**, and provenance stays visible on every card
and claim:

| Original | Replacement |
| --- | --- |
| Salesforce | CRM |
| Jira | Delivery tracking |
| Confluence | Knowledge base |
| Power BI | BI warehouse |
| Granola / call notes | Meeting notes |

Do not remove the provenance chips. They are the point.

## Architecture

### `app.config.js` — single source of brand

Product name, company name, company descriptor, palette, logo, persona in the
header. Nothing branded is hardcoded anywhere else. Palette is navy / crimson /
white; do not carry the teal tokens (`#0fb89c`, `#2d9a8e`, `#35b57e`) across.

### `mock/` — seeded synthetic data

One package, one fixed seed, deterministic output. Demo runs must be identical
every time. Invented firm names only (e.g. Meridian Asset Management, Kestrel
Global Investors, Northgate Fund Services). Fund-industry vocabulary is correct
and stays: transfer agents, distributors, platforms, share classes, domiciles,
mandates, RFP stages, settlement cycles.

### One globe module

The reference has three overlapping globe implementations across
`network-overview`, `market-movement` and `market-research`. Build **one**:
`src/globe/`, using `globe.gl` with country polygons and opportunity markers.

**Do not port the arc / corridor flow layer.** That is the network view, and it
is where the sensitive data lived. Countries with no data render neutral and are
not clickable.

### Country schema

```js
{
  code, name, region,
  marketResearch: Card[],
  presence: { entities, clients, connectedAum, since },
  opportunities: Deal[],
  regulatory: Card[]
}
```

China (`CN`) is the reference implementation — fully populated, every field.
Other countries may be sparse.

### Card schema

Every intelligence card, everywhere:

```js
{ headline, implication, confidence, sourceType, asOf, linkedEntities: [] }
```

`implication` is required. A card that states a fact with no so-what is a news
feed, not intelligence.

### Feature flags

`features.networkView = false`. Flag it off rather than deleting the concept —
it stays available as roadmap.

### Drill-down levels

Each level answers a different question, not just "more rows". Each is a real URL
so any view is deep-linkable.

- **L0** `/` — executive. 6–7 headlines, one sentence each, direction and number.
  Rendered as the spider / business-area view; each spoke is a business area and
  clicking it enters L1. This does not exist in the reference — build it new.
- **L1** `/area/:slug`, `/globe/:country` — what's driving it. Cards and trend.
- **L2** `/area/:slug/:entity` — the account, deal or market. History, owner, open items.
- **L3** `/…/evidence` — underlying records with source chips.

Persistent breadcrumb and context rail across all levels.

### Query field

Scoped, not free-floating. Pass the current view (area, country, selected entity)
into the prompt as context. Put a seeded response cache in front of the live API
call: known demo questions return curated answers instantly, anything else falls
through. Numbers in an answer render as chips that resolve against the mock
dataset; unverifiable claims are visually marked.

## Secrets

`.env` is gitignored. Track `.env.example` with empty values. Never write a key
into a tracked file. API keys live in Vercel project environment variables.

---

## Before every commit

Run the guard:

```bash
./scripts/check-clean.sh
```

It greps the working tree for banned strings and exits non-zero on a hit. If it
fails, fix the file — do not add an exception to the script.

---

## Working style

- Small commits, one concern each.
- When porting, state in the commit message which reference file the logic came
  from, so the lineage is traceable without the code being copied.
- If a task would require reading a file on the never-copy list, stop and ask
  rather than working around it.
